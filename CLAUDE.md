# TourConstructor

## О проекте
Сервис собирает маршрут однодневной поездки из точек (музеи, кафе, гиды) под запрос пользователя.
Пилот: Нижегородская область, только однодневные поездки.

## Архитектура
- Clean Architecture: Domain, Application, Infrastructure, Api в папке src/.
- Domain ни на что не ссылается. В Domain нет EF Core: ни атрибутов, ни using.
- Все зависимости идут внутрь. Infrastructure ссылается на Application, Application ссылается на Domain, API ссылается на всё. 

## Модель данных
- Place — абстрактный базовый класс. В него идёт только то, что истинно для ВСЕХ наследников.
- Attraction - класс, описывающий места интереса для посещения такие как музеи, парки и т.д. Содержит в себе некоторые собственные поля
- Guide - класс, описывающий гидов, которые проводят экскурсии. Содержит в себе некоторые собственные поля
- Dining - класс, описывающий кафе и рестораны. Собственные поля: средний чек (AverageCheck) и длительность визита
- Accommodation - класс, описывающий гостиницы. Собственных полей нет, в планировании времени не участвует и IVisitable не реализует
- IVisitable - интерфейс для мест, визит в которые занимает время (Attraction, Guide, Dining). Планировщик отбирает такие точки через `place is IVisitable`
- Coordinates - сущность типа record, хранит в себе широту и долготу мест
- Tag - класс с Id и Name. Name нормализуется (trim + нижний регистр), равенство и хэш считаются по Name; Id нужен только как ключ в БД
- VisitDuration - класс, который хранит в себе правила для длительности визита

## Правила планировщика
- Жёсткие ограничения (возрастной ценз) — поля. Мягкие предпочтения — теги.
- Рамку одного дня задёт время, необходимое для того чтобы добраться до первой точки в маршруте и время, необходимое чтобы добраться от последней точки до пункта старта всего маршрута
- Принцип выбора точки следующий: жадный выбор: на каждом шаге из точек, которые влезают по времени (визит + дорога + успеваем вернуться), берётся точка с лучшим соотношением «совпадение тегов с запросом / время на дорогу и визит».
- ITravelTimeProvider — «дай время в пути между точками». Реализация через OSRM, сервис /table: матрица запрашивается один раз в начале расчёта, дальше планировщик работает с ней в памяти. IPlaceRepository — «дай заведения». Реализация через EF и PostgreSQL.
Оба интерфейса в Application, реализации в Infrastructure.

## Не делать
- Не использовать рейтинги и отзывы. Ценность точки считается только по совпадению тегов с запросом.
- Не парсить сайты отелей, ресторанов и агрегаторов: нарушает условия площадок и даёт ненадёжные цены.
- Не использовать Яндекс.Расписания: условия запрещают коммерческое использование и хранение данных.
- Не строить маршрут через LLM: он не гарантирует, что маршрут физически складывается. LLM допустим только позже, для разбора текстового запроса в параметры.
- Не делать вторую базу данных и микросервисы. Одна БД, модули разделены через интерфейсы.
- Не добавлять RabbitMQ, Redis, Elasticsearch, Hangfire без явной задачи.
- Не делать Telegram Mini App: фронтенд будет отдельным приложением.
- В пилоте только однодневные поездки. Accommodation есть в модели, но планировщик его не использует.
- Не делать бронирование: пользователь получает ссылки и контакты.
- Не добавлять поля и сущности «на будущее» без явной задачи.

## Команды
```powershell
# 1. Построить граф из карты (долго, ест много памяти)
docker run -v "${PWD}:/data" ghcr.io/project-osrm/osrm-backend osrm-extract -p /opt/car.lua /data/volga-fed-district-260915.osm.pbf

# 2. Разбить граф на ячейки
docker run -v "${PWD}:/data" ghcr.io/project-osrm/osrm-backend osrm-partition /data/volga-fed-district-260915.osrm

# 3. Проставить веса
docker run -v "${PWD}:/data" ghcr.io/project-osrm/osrm-backend osrm-customize /data/volga-fed-district-260915.osrm

# 4. Запустить сервер на порту 5000
docker run -p 5000:5000 -v "${PWD}:/data" ghcr.io/project-osrm/osrm-backend osrm-routed --algorithm mld /data/volga-fed-district-260915.osrm

запускать из папки osrm/, шаги 1–3 один раз, экстракт с Geofabrik (Приволжский ФО), плюс dotnet build и dotnet test.
```
